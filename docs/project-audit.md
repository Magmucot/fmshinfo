## 1. Архитектурный обзор проекта

Проект представляет собой комплексный агрегатор информации для учащихся, преподавателей и родителей **Специализированного учебно-научного центра Новосибирского государственного университета (СУНЦ НГУ / ФМШ)**.

### Состав системы:
1. **Основной веб-портал (Next.js 16 + React 19 + Tailwind CSS v4 + Radix UI / shadcn):**
   - 11 интерактивных разделов: Дашборд, Столовая (Меню + График смен + Аналитика КБЖУ), Расписание звонков и пар, Мероприятия школы, Дежурства, Ночные вожатые, Погода в Академгородке, Новости СУНЦ, Справочник/Контакты, Гайд пользователя, Документация.
   - PWA с поддержкой офлайн-режима, манифестом и установкой как мобильное приложение.
2. **Серверный слой API (Next.js Route Handlers):**
   - 13 маршрутов: `/api/menu`, `/api/menu/stats`, `/api/canteen/schedule`, `/api/bells`, `/api/classes`, `/api/schedule`, `/api/events`, `/api/weather`, `/api/news`, `/api/duty`, `/api/counselors`, `/api/feedback`, `/api/info`.
   - Кэширующий слой `cache.ts` с поддержкой TTL и stale-while-revalidate.
3. **База данных (SQLite + Prisma ORM):**
   - Локальная база `db/custom.db`, управляющая дежурствами (`DutyEntry`), ночными вожатыми (`NightCounselor`) и обращениями (`Feedback`).
4. **Telegram-бот (`mini-services/tg-bot` на фреймворке grammY):**
   - Автономный сервис на порту 3003, синхронизированный с REST API портала.
   - Поддерживает спящий режим без токена (healthcheck активен) и рабочий long-polling режим.
5. **FastAPI-бэкенд (`fastapi-backend/`):**
   - Эталонный микросервис на Python 3 с асинхронными парсерами `httpx` и `BeautifulSoup4`.

## 2. Найденные и устранённые критические дефекты

### 2.1. Критическая ошибка: Путь к базе данных в `.env`
- **Проблема:** В файле `.env` было жёстко прописано `DATABASE_URL=file:/home/z/my-project/db/custom.db` (путь из старого контейнера разработки). При любых запросах к дежурствам, вожатым или отправке обратной связи Prisma выбрасывала ошибку `database file does not exist`.
- **Решение:** Путь обновлён на актуальный `/home/magus/code/projects/FMSH_gemini/db/custom.db`. Настроены переменные для корректной работы Prisma Client на NixOS. База успешно инициализирована, данные сохранены.

### 2.2. Критическая ошибка классификации занятий: «Спецкурс» вместо «Семинара»
- **Проблема:** В коде `src/lib/server/tableSesc.ts` и `schedule_parser.py` тип занятия мапился вслепую:
  ```typescript
  // БЫЛО (ОШИБКА):
  1: "Урок", 2: "Спецкурс", 3: "Факультатив"
  ```
  В реальности в системе table-sesc.nsu.ru (исследовано через JS бандл `app.b5484b70.js`):
  ```javascript
  Ps = 1, Ys = 2, Js = 3;
  $s = { getLabel: (e) => (1 === e ? "лек" : 2 === e ? "пр" : 3 === e ? "лаб" : "") };
  ```
  Из-за этой ошибки все стандартные семинары (математика, русский язык, английский, химия, физика) в интерфейсе и боте ложно маркировались как «Спецкурс», а поточные лекции — как «Урок».
- **Решение:**
  - `type: 1` → **Лекция** (`лек` / `lesson-type_lecture`)
  - `type: 2` → **Семинар / Практика** (`пр` / `lesson-type_practice`)
  - `type: 3` → **Лабораторная работа** (`лаб` / `lesson-type_lab`)
  - Реализован интеллектуальный классификатор `classifyLesson`, который распознаёт спецкурсы и факультативы по их фактическому названию (`"Спецкурс"`, `"СК"`, `"Факультатив"`).

### 2.3. Критическая ошибка распределения мероприятий по классам (Google Sheets)
- **Проблема:**
  1. В школьной Google-таблице мероприятий пересдачи для нескольких классов записывались в одной ячейке, например: `Физ пересдача 15:00 (11-1,11-2, 11-3) ауд. 4.2.` в колонке 11-1. Прежний парсер смотрел только на индекс колонки, поэтому учащиеся 11-2 и 11-3 эту пересдачу не видели.
  2. Общешкольные события («КАНИКУЛЫ», «ДЕНЬ САМОУПРАВЛЕНИЯ», «Посвящение в ФМШата», «Генеральная уборка в общежитиях», «Презентация спецкурсов») в Google Sheets находились в объединённых ячейках всей строки. Google Sheets при экспорте в CSV помещает текст в крайнюю левую ячейку (`8-1` или `9-1`), оставляя остальные 24 колонки пустыми. В результате каникулы и день самоуправления отображались только у 8-1 класса!
- **Решение:**
  - Разработан алгоритм `resolveTargetClasses`:
    - Извлекает явные списки классов из текста: `(11-1, 11-2, 11-3)`, `11-5,6`, `9-1,2,3`, `11-8`.
    - Распознаёт параллели: `ОГЭ` → 9-е классы, `ЕГЭ / КЕГЭ` → 11-е классы, `10 класс...` → 10-е классы.
    - Распознаёт общешкольные ключевые слова и относит их ко всем классам школы (`isGeneral: true`).
    - Каждому событию присваивается категория (`classifyEvent`): `Лекция`, `Спецкурс`, `Семинар / Консультация`, `Экзамен / Пересдача`, `Уборка / Дежурство`, `Мероприятие`.

### 2.4. Отсутствие графика питания столовой по сменам
- **Проблема:** На портале отображалось меню блюд, но не было информации о том, в какое время какой класс идёт на завтрак, обед и ужин.
- **Решение:**
  - Оцифрован официальный документ `rasp.jpg` («График работы столовой со 2 сентября»).
  - Создан модуль `src/lib/server/canteenSchedule.ts` и эндпоинт `/api/canteen/schedule`.
  - Учтены смены:
    - **1-я смена:** `8-1`, `11-1 … 11-9`, `11-11`, `11-12` (Обед 14:15, Ужин 19:30).
    - **2-я смена:** `10-1 … 10-9` (Обед 14:30, Ужин 19:40).
    - **3-я смена:** `9-1 … 9-3`, `11-10` (Обед 14:45, Ужин 19:50).
    - **Дежурные по столовой** (накрытие столов) и **Опоздавшие**.
    - Режим выходных и праздничных дней (завтрак 8:35, 2-го завтрака и 2-го ужина нет).
  - В раздел «Столовая» встроен переключатель `Меню | График смен | Аналитика` с персональным выбором класса и живым статусом «Сейчас в столовой».
  - На дашборд добавлена строчка живого статуса столовой и прямой переход к графику смен.

## 3. Аудит и модернизация Telegram-бота (`mini-services/tg-bot`)

Бот проверен и расширен:

### Добавленный функционал:
1. **Команда `/canteen` (или `/canteen <класс>`):**
   - Показывает текущий статус столовой (кто сейчас питается, через сколько следующий приём пищи).
   - Выводит персональное время приёмов пищи для указанного класса или общую сетку 3 смен, дежурных и опоздавших.
   - Поддерживает инлайн-кнопки переключения смен.
2. **Команда `/now` («Что сейчас в школе»):**
   - Текущий урок / перемена с расчётом оставшихся минут.
   - Текущее состояние столовой для смены пользователя.
   - Погода в Академгородке.
   - Дежурный класс на сегодня.
3. **Запоминание класса (`/setclass <класс>` и `/myclass`):**
   - Пользователь один раз указывает свой класс (например, `/setclass 10-1`).
   - Команды `/schedule`, `/tomorrow`, `/canteen`, `/now`, `/events` автоматически подтягивают данные для сохранённого класса.
4. **Поиск преподавателя и аудитории (`/find <запрос>`):**
   - Например, `/find Горшков` или `/find 2_10` — выводит расписание преподавателя или занятость кабинета по дням недели.
5. **Исправление типов занятий в расписании:**
   - В тексте уроков выводятся теги `[Лекция]`, `[Семинар]`, `[Спецкурс]`, `[Лабораторная]`.
6. **Интерактивные клавиатуры:**
   - Постоянное нижнее меню (`ReplyKeyboardMarkup`): `🍽 Меню`, `📅 Расписание`, `🍱 Столовая`, `⚡ Сейчас`, `🔔 Звонки`, `📌 Мероприятия`, `🌤 Погода`.
   - Инлайн-переключатели дней недели (`Пн`, `Вт`, `Ср`, `Чт`, `Пт`, `Сб`) в `/schedule`.
   - Инлайн-переключатели дат в `/menu`.
