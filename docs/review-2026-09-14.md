# Ревью проекта — 14 сентября 2026

## Исправлено

- POST `/api/users/telegram` позволял без авторизации изменять профили и получать персональные данные в ответе. Теперь доступ проверяется до чтения тела и обращения к БД.
- Убрана авторизация встроенным паролем `sunc-admin`: административные маршруты закрыты без непустого `ADMIN_KEY`.
- Сайт и бот передают административный ключ заголовком `X-Admin-Key`; ключи в URL больше не принимаются. Приватная статистика бота не попадает в общий кэш.
- Синхронизация профилей бота ограничена таймаутом; HTTP-ошибки больше не считаются успешной синхронизацией.
- Параметры отключения предпросмотра ссылок приведены к установленным типам Telegram API; отсутствующие поля английских групп нормализованы.
- Исправлены типы PWA-инициализации и слотов расписания. Проверка TypeScript включена в production-сборку, добавлена команда `npm run typecheck`. Демонстрационные websocket-файлы и отдельный диагностический скрипт исключены из проверки приложения; бот включён с типами Bun.
- Явно указан корень Next.js: иначе внешний package-lock.json менял расположение standalone/server.js и ломал команду запуска.

## Второй проход: профили и обратная связь

- Профили Telegram и веб-посетителей сохраняются атомарным `upsert`, без гонки findUnique/create при первой регистрации.
- Частичное обновление сохраняет пропущенные поля; явный `null` очищает nullable-поля. Пропущенный `isPremium` больше не сбрасывает Premium.
- Добавлена проверка типов, длины строк, ID и допустимых подгрупп. Неверные тела профилей и обратной связи возвращают 400; сбои хранилища возвращают 500 с общим сообщением вместо внутренней ошибки Prisma.
- Публичный POST веб-посетителей больше не возвращает сохранённый профиль по переданному clientId.
- `npm run test:unit` проверяет авторизацию и входные данные. `npm run test:api` после сборки запускает standalone-сервер и создаёт временную SQLite-базу из актуальной Prisma-схемы, удаляемую после теста.
- HTTP-тест прошёл: 8 конкурентных регистраций Telegram, счётчик 9 после следующего запроса, сохранение пропущенных полей, явная очистка, 8 конкурентных регистраций веб-посетителя, авторизация, валидация и сохранение обратной связи.
- Проверки TypeScript, ESLint и production-сборка прошли. Для Prisma на текущем NixOS тест использовал локальные движки из `.prisma-engines` через `PRISMA_QUERY_ENGINE_LIBRARY`/`PRISMA_SCHEMA_ENGINE_BINARY` и OpenSSL 3 в `LD_LIBRARY_PATH`; запуск дочерних процессов требовал выхода из песочницы.

Остальные HTTP-маршруты, интерфейс в браузере и сценарии Telegram ещё требуют проверки. Проверенные профили не означают завершение ревью всего проекта.

## Третий проход: выбор класса и подгрупп (15 сентября)

- Смена класса сбрасывает обе подгруппы; повторный выбор того же класса сохраняет настройки. Профиль и синхронизация берут фильтры из актуальных карт настроек, без восстановления удалённых значений из старого профиля.
- Все пять обработчиков меню/выбора подгрупп проверяют соответствие кнопки сохранённому классу. Для английского проверка повторяется после загрузки вариантов. Устаревшие кнопки предлагают заново открыть `/subgroup`.
- Просмотр расписания другого класса не применяет личные фильтры и не предлагает настройку чужих подгрупп.
- Кнопка расписания «сегодня» в воскресенье больше не подменяет день понедельником. Значение дня проверяется до запроса расписания.
- `npm run test:unit`: добавлены сценарии смены класса, повторного выбора, возврата к прежнему классу, независимости пользователей и перехода суток по Новосибирску. TypeScript и линтер проходят. Живые сообщения Telegram не отправлялись; тесты проверяют выделенную логику, обработчики дополнительно просмотрены в diff.

Остаётся проверить стабильность выбора английского при изменении списка вариантов (кнопки пока содержат индекс), сохранение при перезапуске и полные сценарии Telegram на тестовом транспорте.

## Проверка сайта в Chromium (15 сентября)

Проверены 10 разделов на ширине 390 px с отказами API, заполненные расписание и меню на тестовых данных, ширина 1440 px, поиск/сброс поиска блюд, выбор класса и сохранение после перезагрузки. Внешние источники в этих браузерных тестах подменены: их актуальность и доступность эти проверки не подтверждают.

Исправлено:
- URL обновляется при смене раздела и режима столовой; перезагрузка, Back/Forward и горячие клавиши сохраняют согласованное состояние. Старая ссылка `?tab=analytics` продолжает открывать аналитику.
- Убрана ошибка гидратации React из-за даты сборки статической главной страницы. Дата появляется после гидратации, часы главной обновляются каждые 15 секунд.
- Недоступность звонков больше не выдаётся за окончание учебного дня. В воскресенье не показывается текущий урок из будничной сетки звонков.
- Убрана неработающая подсказка Alt+10 у раздела аудитории (поддерживаются Alt+1…9).

После изменений: нет ошибок pageerror в Chromium, нет горизонтального переполнения страницы в проверенных состояниях; TypeScript, ESLint и production-сборка проходят. Тест выбора класса исправлен под фактическое имя пункта «11-1 класс»; дефекта выбора класса не обнаружено.

Повторяемые браузерные сценарии: `tests/site-navigation.cjs`, `tests/site-content.cjs`. Запускать против локальной сборки, например `SITE_URL=http://127.0.0.1:3198 PLAYWRIGHT_MODULE=/путь/к/playwright CHROMIUM_PATH=/путь/к/chromium node tests/site-navigation.cjs`. Для второго сценария заменить имя файла. По умолчанию модуль загружается как `playwright`; в текущем окружении использован имеющийся npm-кэш и системный Chromium. Тесты не отправляют формы в рабочую БД.

Ещё не проверены браузером: реальные внешние источники, отправка административных форм, офлайн/PWA-установка и полный набор состояний аналитики. Полный аудит проекта остаётся незавершённым.
