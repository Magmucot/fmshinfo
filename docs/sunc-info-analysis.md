## 1. Введение и цель документа

**СУНЦ НГУ** (Специализированный учебно-научный центр НГУ, «ФМШ», «Физматшкола им. М. А. Лаврентьева») — школа-интернат при НГУ в новосибирском Академгородке (630090, г. Новосибирск, ул. Пирогова, здание 4). Официальный сайт: **https://sesc.nsu.ru**.

Ученикам, родителям и сотрудникам ежедневно требуется следующая оперативная информация:

1. **Меню столовой** (6-разовое питание)
2. **Расписание звонков**
3. **Расписание занятий** по классам
4. **График дежурств** (классов, по столовой, по корпусам)
5. **График ночных вожатых / воспитателей**
6. **Погода** рядом со школой (Академгородок)
7. **Новости и объявления**, полезные контакты и ссылки

Цель документа — зафиксировать, **где именно публикуется каждый тип данных, в каком формате, с какой частотой обновляется**, и определить **алгоритмы парсинга** так, чтобы на основе этой информации можно было построить сайт и/или Telegram-бота с автоматическим обновлением.

## 3. Детальный анализ источников

### 3.1. Меню столовой (ЕЖЕДНЕВНОЕ МЕНЮ) — главный «продуктовый» источник

**Страница-каталог:** `https://sesc.nsu.ru/sveden/catering`
(раздел «Сведения об образовательной организации» → «Организация питания в образовательной организации»).

На странице публикуются ссылки на PDF-файлы ежедневного меню. Паттерн имени файла:

```
/upload/iblock/<32-символьный хэш>/menu_ДД.ММ.ГГ.pdf
```

Пример реальных ссылок (проверено 30.08.2026):

```
https://sesc.nsu.ru/upload/iblock/048/g1v8y0cnh21sw24qjvl1r96mt1plmal2/menu_25.08.26.pdf
https://sesc.nsu.ru/upload/iblock/e17/b1z4tiv06cln7jf1lliisik4h2z9aidf/menu_30.08.26.pdf
https://sesc.nsu.ru/upload/iblock/ecb/m9mafk5r6ncc19ydzyjfeb6v7uduv4ca/menu_08.09.26.pdf
```

**Важно:** `<hash>` в пути меняется при каждой загрузке нового файла (CMS «1С-Битрикс»), поэтому **нельзя захардкодить URL меню** — нужно каждый раз парсить страницу `/sveden/catering` и извлекать актуальные ссылки.

**Структура PDF (проверено на menu_30.08.26.pdf, 2 страницы):**

- Заголовок: «Меню школы (СУНЦ НГУ)», дата в шапке
- Приёмы пищи (секции): **Завтрак, Обед, Полдник, Ужин, Второй ужин** (шестиразовое питание)
- Для каждого блюда: **выход (г)**, **наименование блюда**, **энергетическая ценность** (строки вида `Ккал-560, Белки-13, Жиры-17, Углеводы-91`), для основных блюд — **состав/ингредиенты** (строка начинается с перечня продуктов)
- После каждой секции: строка «Итого за <приём пищи> Ккал-…, Белки-…, Жиры-…, Углеводы-…»

**Алгоритм парсинга меню:**

1. `GET https://sesc.nsu.ru/sveden/catering` с User-Agent браузера.
2. Регулярным выражением `href="([^"]*menu_\d{2}\.\d{2}\.\d{2}\.pdf)"` собрать все ссылки на PDF + имена файлов.
3. Из имени файла извлечь дату (`menu_30.08.26.pdf` → 30.08.2026).
4. Выбрать файл нужной даты (или ближайший доступный).
5. Скачать PDF (кэшировать на диске, TTL до конца дня).
6. Извлечь текст: `pdftotext -layout menu.pdf -` (или pdfplumber в Python).
7. Разобрать текст:
   - секции: строки `Завтрак / Обед / Полдник / Ужин / Второй ужин` (регистр может отличаться);
   - блюдо: число (выход в граммах) в начале строки + название;
   - КБЖУ: строки, содержащие `Ккал-`;
   - итоги: строки `Итого за <секция>`;
   - ингредиенты: строки между блюдом и следующей «числовой» строкой.
8. Вернуть структурированный JSON.

**Целевая JSON-структура:**

```json
{
  "date": "30.08.2026",
  "source": "https://sesc.nsu.ru/sveden/catering",
  "pdfUrl": "https://sesc.nsu.ru/upload/.../menu_30.08.26.pdf",
  "availableDates": ["30.08.2026", "31.08.2026", "..."],
  "meals": [
    {
      "type": "Завтрак",
      "dishes": [
        {
          "weight": 200,
          "name": "Каша молочная рисовая",
          "kcal": 220, "protein": 5, "fat": 7, "carbs": 33,
          "ingredients": "Сахар, Масло сливочное, Крупа рисовая (кругл), Молоко, Соль йодированная"
        }
      ],
      "totals": {"kcal": 560, "protein": 13, "fat": 17, "carbs": 91}
    }
  ]
}
```

**Частота опроса:** страница каталога — 1 раз в час достаточно (меню публикуется заранее на ~2 недели); кэш разобранного меню — до конца дня.

### 3.3. Расписание занятий (по классам / преподавателям / аудиториям)

**Сервис:** `https://table-sesc.nsu.ru` — SPA на Vue.js (та же кодовая база, что и расписание НГУ). Открытое API без авторизации (авторизация нужна только для бронирования аудиторий).

**Эндпоинты:**

| Эндпоинт | Назначение | Параметры |
|----------|-----------|-----------|
| `GET /api/school-class` | Список классов (8-1 … 11-7, ~25 классов) | — |
| `GET /api/schedule/find` | Расписание | `group` (напр. `10-1`), `teacher`, `classroom` — одновременно задаётся **один** из фильтров |
| `GET /api/teacher` | Список преподавателей | фильтр по букве |
| `GET /api/teacher/filters` | Буквы для фильтра преподавателей | — |
| `GET /api/classroom` | Список аудиторий | фильтр |
| `GET /api/classroom/filters` | Этажи для фильтра аудиторий | — |
| `GET /api/bell` | Расписание звонков | — |
| `POST /api/classroom/reserve`, `POST /api/reserve` | Бронирование аудиторий | **требует OAuth** — не использовать |

**Формат ответа `/api/schedule/find?group=10-1`:**

```json
{
  "payload": {
    "schedule": {
      "1-08:30": [{
        "id": 74245,
        "weekday": 1,                          // 1 = понедельник, 6 = суббота
        "time": {"id": 65, "begin": "08:30", "end": "09:15"},
        "lesson": {"id": 6388, "name": "Физика", "type": 1},
        "classroom": {"id": 30, "name": "5_6"}, // может быть null
        "teacher": {"id": 8196, "name": "Горшков Д.В."},
        "schoolClasses": [{"id": 9497, "name": "10-1", "parallel": 10, "subgroup": null}],
        "date": "2026-09-01"                    // для датированных уроков, обычно null
      }],
      "1-09:25": [ ... ], "2-08:30": [ ... ]
    }
  }
}
```

**Ключи расписания:** `"<weekday>-<HH:MM>"` — день недели + начало урока. `weekday`: 1=Пн … 6=Сб (воскресенье — выходной). `lesson.type`: 1 = обычный урок, 2 = спецкурс/факультатив (уточняется по данным).

**Частота опроса:** 1 раз в час + ручное обновление по кнопке. Кэш по ключу (тип фильтра + значение).

### 3.4. Дежурства — ВАЖНЫЙ ВЫВОД

Комплексный поиск по сайту sesc.nsu.ru, сервису table-sesc.nsu.ru, сайтам НГУ (nsu.ru), новостям и соцсетям показал:

**График дежурств классов (по столовой, корпусам, этажам общежитий) в открытом доступе НЕ публикуется.** Данная информация доводится:

- через информационные стенды в учебном корпусе и общежитиях;
- через воспитателей и ученическое самоуправление (объявления в классах/чатах);
- через электронный журнал (закрыт авторизацией).

**Рекомендация для сайта/бота:** реализовать модуль «Дежурства» с **ручным вводом через административную панель** (или команду боту от ответственного администратора с проверкой секретного ключа). Модель данных:

```
DutyEntry {
  id, date (ДД.ММ.ГГГГ), weekday,
  duty_type: 'столовая' | 'корпус' | 'общежитие' | 'медпункт' | 'прочее',
  class_name (напр. '10-2'), responsible (ФИО ответственного, опц.),
  time_interval (напр. 'после 3 урока'), notes
}
```

До ввода реальных данных допустимо отображать заглушку «Данные обновляются администратором» + справочную информацию о порядке дежурств.

### 3.5. Ночные вожатые — ВАЖНЫЙ ВЫВОД

Аналогично дежурствам: **график ночных дежурств воспитателей/вожатых в интернете не публикуется.** Из открытых источников известно только общее описание (FAQ сесс. сайта): «в общежитиях организовано **круглосуточное дежурство воспитателей** с обходами общежитий; в любое время обучающийся может обратиться к дежурному воспитателю».

Конкретные ФИО и телефоны ночных дежурных доводятся:

- стендами на этажах общежитий №1 и №2;
- внутренней рассылкой / чатами родителей;
- через дежурного воспитателя (вход в общежития с 20:00 до 08:00 — через 1-е общежитие).

**Рекомендация:** модуль «Ночные вожатые» с ручным администрированием, аналогично п. 3.4:

```
NightCounselor {
  id, date, dormitory: 'Общежитие №1' | 'Общежитие №2',
  counselor_name, phone (внутренний/сотовый, опц.), floor/room (опц.), notes
}
```

Плюс статический блок «Экстренные контакты» (охрана, медпункт, горячая линия).

### 3.6. Погода рядом с СУНЦ НГУ (Академгородок)

**Координаты СУНЦ НГУ: 54.842° с.ш., 83.098° в.д.** (Новосибирск, Советский район, Академгородок, ул. Пирогова).

**Источник A (основной): Open-Meteo** — бесплатно, без API-ключа:

```
GET https://api.open-meteo.com/v1/forecast
  ?latitude=54.842&longitude=83.098
  &current=temperature_2m,relative_humidity_2m,apparent_temperature,
           weather_code,wind_speed_10m,wind_direction_10m
  &daily=weather_code,temperature_2m_max,temperature_2m_min,sunrise,sunset,precipitation_probability_max
  &timezone=Asia/Novosibirsk&forecast_days=3
```

WMO weather_code → русские описания (0 «Ясно», 1–2 «Малооблачно», 3 «Пасмурно», 45/48 «Туман», 51–67 «Морось/Дождь», 71–77 «Снег», 80–82 «Ливни», 95–99 «Гроза»).

**Источник B (резервный): wttr.in** — `https://wttr.in/Akademgorodok?format=j1` (JSON: current_condition[], weather[] на 3 дня; коды WWO — 113 «Ясно», 116 «Переменная облачность», 200 «Гроза», …).

**Частота опроса:** не чаще 1 раза в 10 минут, кэш 10 минут. Рекомендуется показывать: текущую температуру, «ощущается как», ветер, влажность, прогноз на 3 дня, время рассвета/заката (важно для школьников в интернате).

### 3.7. Новости СУНЦ НГУ

**Каталог:** `https://sesc.nsu.ru/media/news/` (постраничная разбивка; на первой странице ~12–25 новостей).

**Структура HTML (CMS 1С-Битрикс):**

- ссылка новости: `<a href="/media/news/<рубрика>/<id>/">Заголовок</a>`, рубрики: `obrazovanie`, `atmosfera`, `nauka` и др.;
- дата рядом с новостью в формате `ДД.ММ.ГГГГ`;
- страница новости содержит `<h1>Заголовок</h1>`, дату и текст в блоке detail.

**Алгоритм:** GET каталога → regex `href="/media/news/[^"]+"` → уникализация → сопоставление с датами `(\d{2}\.\d{2}\.\d{4})` → выдача топ-N.

**Частота:** 2–4 раза в сутки. Также рекомендуется RSS-лента, собранная из этого парсера.

## 4. Модель данных агрегатора (сайт/бот)

```
┌─────────────────────┐   ┌──────────────────────┐   ┌───────────────────────┐
│ MenuDay             │   │ BellSchedule         │   │ ClassSchedule         │
│ date: Date (PK)     │   │ id, begin, end, pair │   │ group, weekday, time, │

│ totals: JSON        │                              └───────────────────────┘
└─────────────────────┘
┌─────────────────────┐   ┌──────────────────────┐   ┌───────────────────────┐
│ DutyEntry (admin)   │   │ NightCounselor(admin)│   │ NewsItem              │
│ date, type, class,  │   │ date, dormitory,     │   │ id, title, url, date, │
│ responsible, notes  │   │ name, phone, notes   │   │ rubric                │
└─────────────────────┘   └──────────────────────┘   └───────────────────────┘
┌─────────────────────┐   ┌──────────────────────┐
│ WeatherCache        │   │ Feedback             │

└─────────────────────┘   └──────────────────────┘
```

- `MenuDay`, `ClassSchedule`, `BellSchedule`, `NewsItem`, `WeatherCache` — **получатели** (парсеры, автообновление).
- `DutyEntry`, `NightCounselor` — **редактируемые** (админ-панель, ключ администратора).
- `Feedback` — обратная связь с сайта.

## 5. Спецификация REST API агрегатора

| Метод | Endpoint | Описание | Источник |
|-------|----------|----------|----------|
| GET | `/api/menu?date=ДД.ММ.ГГ` | Меню столовой на дату + список доступных дат | Парсер PDF |

**Рекомендуемые интервалы автообновления (cron):** меню — каждый час; расписание/звонки — каждый час; новости — каждые 6 часов; погода — каждые 10 минут; очистка старых записей — раз в сутки.

## 6. Архитектура решения

**Вариант «Сайт + API» (FastAPI, эталонная реализация в `/fastapi-backend`):**

```
fastapi-backend/
├── main.py              # FastAPI: эндпоинты из таблицы выше, кэш в памяти, CORS
├── parsers/
│   ├── menu_parser.py       # каталог → PDF → текст (pdfplumber/pdftotext) → JSON
│   ├── schedule_parser.py   # клиент table-sesc.nsu.ru (bells, classes, schedule)
│   ├── news_parser.py       # HTML → список новостей (regex/BeautifulSoup)
│   └── weather.py           # Open-Meteo (осн.) + wttr.in (резерв)
├── database.py          # SQLite/SQLAlchemy: DutyEntry, NightCounselor, Feedback
├── models.py            # Pydantic-схемы
├── static/index.html    # одностраничный сайт-агрегатор (fetch → рендер)
└── requirements.txt     # fastapi, uvicorn, httpx, pdfplumber, beautifulsoup4, ...
```

**Вариант «Telegram-бот» (aiogram 3):** те же парсеры; команды `/menu`, `/bells`, `/schedule 10-1`, `/weather`, `/news`, `/duty`, `/night`; ежедневная авторассылка меню в 7:30 (Asia/Novosibirsk) подписанным классам; инлайн-клавиатуры для выбора класса/даты; админ-команды с проверкой ID администраторов для дежурств и вожатых.

**Общие правила надёжности:**

1. Все внешние запросы — с таймаутом 15–20 с и 2 повторами.
2. Кэш в памяти с TTL (меню/расписание 60 мин, погода 10 мин, новости 6 ч).
3. При недоступности источника — отдаётся последний успешный результат с пометкой `stale: true`.
4. User-Agent браузера обязателен для sesc.nsu.ru (защита от простых ботов).
5. Не запрашивать источники чаще указанных интервалов (уважение к серверам НГУ).

## 7. Риски и ограничения

| Риск | Вероятность | Митигация |
|------|-------------|-----------|
| Смена хэшей URL PDF-меню | 100% (каждый день) | Всегда парсить каталог `/sveden/catering`, не хардкодить ссылки |
| Изменение вёрстки сайта (Bitrix) | Низкая | Резервные регулярные выражения + уведомление админу при пустом результате |
| Ограничение API open-meteo по IP | Средняя | Резервный источник wttr.in |
| Отсутствие дежурств/вожатых онлайн | 100% | Ручной ввод через админку (спроектировано) |
| table-sesc без документации | — | Формат стабилен с 2024 г., эндпоинты зафиксированы в данном документе |
| Летние каникулы: меню не публикуется | Высокая (июнь–август) | Показывать последнее доступное меню с пометкой даты |
